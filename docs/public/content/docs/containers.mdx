**Containers** lists every container on your servers with its status,
stack, CPU, memory, uptime, networks and ports. Search by name, image,
address or label, and filter by status, stack or available updates.

## Start, stop and remove

On a container's page, one button shows **Stop** while it runs and
**Start** when it doesn't. Its menu has **Start**, **Restart** and
**Stop**. Next to it, **Pause** freezes a running container and **Unpause**
resumes a paused one. **Remove** is under **More Actions**. The same
actions are in each row's menu in the list.

- **Stop** asks first.
- **Remove** asks you to type the container's name.

To act on several containers, tick their rows and pick an action in the bar
above the list. You see which containers it runs on and which are left out,
and why.

You can start and stop a stack's containers here, but you change or remove
them through the [stack](/stacks).

## Recreate a container

**Recreate** replaces a container with a new one from the same settings.

1. On the container's page, open **More Actions → Recreate…** (or the
   row's menu in the list).
2. Check what happens and press **Recreate**.

- Only for containers outside a stack or Compose project. For a stack's
  container, use **Force Recreate** in its service's row on the
  [stack](/stacks) page.
- It uses the image as it is on the server now and downloads nothing. To
  run a newer version, pull the image on **Images** first.
- Volumes are kept. Changes made inside the container outside a volume are
  lost.
- The new container starts only if the old one was running.

## A container's page

- **Overview**: CPU, memory, restarts and health, a chart, and its image,
  ports, networks, mounts, labels and limits. For containers Docker Manager
  created, it shows the names of the environment variables, never their
  values.
- **Logs** and **Terminal**: see [Logs](/logs) and
  [Terminal](/terminal).

**Settings** changes the restart policy and the CPU, memory and process
limits. Other settings need a new container.

## Create a container

For a single container without a Compose file, press **Create Container**.
Fill in the image (for example `nginx:1.27`) and a name, and optionally
environment variables, ports, volumes, networks, restart policy, limits
and, under **Advanced**, the command, user, health check and labels. Then
press **Create Container**.

Creating never downloads the image: if it is missing, press **Pull Image**
first. Environment variable values are stored encrypted and never shown
again.

## Docker Manager's own containers

Docker Manager never stops, pauses, recreates or removes its own manager and agent,
and never removes its own images, volumes or networks. Nobody can change
this, not even the owner.
