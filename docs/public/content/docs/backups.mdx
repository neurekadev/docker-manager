---
title: Backups
description: Back up and restore your stacks, volumes and Docker Manager itself.
---

Docker Manager backs up your stacks (their folder and volumes), your other
volumes and its own data. Backups are encrypted and stored in a
**repository**: S3-compatible storage or a folder on a server. The owner
adds repositories; people with permission can create backup policies.

## 1. Add a repository

1. Open **Backups** and press **Add repository**.
2. Enter a **Name** and choose the **Storage**:
   - **S3-compatible storage**: the **Endpoint**, **Bucket**, **Access key
     ID** and **Secret access key**. This is the easiest choice, and the
     only one that holds backups of every server.
   - **Local directory**: a folder on one server (**Written by**). Allow
     the folder first (see [Allow a local folder](#allow-a-local-folder)).
3. Choose the **Compression**. **Automatic** suits most data.
4. Press **Save and continue**.
5. The first time, Docker Manager shows your **Recovery Key**. Store it
   outside Docker Manager and press **I saved it, continue**.
6. Paste the key, tick that you saved it and press **Confirm Recovery
   Key**. Later repositories use the same key and ask you to type it again.

<Callout type="warn" title="Keep the Recovery Key safe">
  One Recovery Key encrypts all your backups, and it is shown only once.
  You need it to restore on a new Docker Manager, for example after losing
  the server it ran on. Without it, nobody can open your backups.
</Callout>

## 2. Create a backup policy

A **backup policy** says what to back up, where, when and for how long.
Each server can be covered by one policy.

1. Press **Create backup policy**.
2. **Destination**: a **Name**, the **Environments** and the
   **Repository**.
3. **What to back up**: every stack and volume is included, and stacks you
   add later too. Untick what to leave out.
   - Turn on **Back up the manager state** to back up Docker Manager itself.
   - **Stop containers during backups** is off: apps keep running. Turn it
     on for databases that need a clean copy.
4. **Schedule**: turn on **Back up automatically** and pick when.
5. **Retention**: how many backups to keep. **7 daily, 4 weekly, 12
   monthly** is a good start.
6. Press **Create policy**.

**Preview what gets backed up** shows the exact list. **Back up now** on
the policy runs it right away, and **Retry missing** backs up only what
failed.

To stop a backup, press **Cancel** next to it under **Running now** on the
**Backups** page, then **Cancel backup**. It stops shortly: what it
already backed up is kept, the rest is left out until **Retry missing**,
and containers it stopped start again. Each server's backup is cancelled
on its own.

<Callout type="warn" title="Back up Docker Manager itself">
  Turn on **Back up the manager state** in one policy, and store it away
  from the manager's disk (S3, or a network share). Otherwise a lost disk
  means a lost Docker Manager.
</Callout>

## What is not backed up

- Folders a stack mounts from outside its own folder, such as
  `/srv/media:/media`, unless you [allow them](#back-up-folders-outside-a-stack).
- Anonymous volumes, unless you turn on **Back up anonymous volumes**.
- Volumes with the label `docker-manager.backup.exclude=true`, and the
  volumes of a container with that label.

## Back up folders outside a stack

A stack can mount a folder of the server from outside its own folder, such
as `/srv/media`. To back it up:

1. Allow the folder on that server's agent: mount it at the same path and
   list it in `DOCKER_AGENT_BACKUP_EXTERNAL_ALLOWLIST` (several folders
   separated by commas).

   ```yaml title="compose.yaml"
   services:
     docker-agent:
       environment:
         # ...keep the existing lines...
         DOCKER_AGENT_BACKUP_EXTERNAL_ALLOWLIST: /srv/media
       volumes:
         # ...keep the existing lines...
         - /srv/media:/srv/media
   ```

2. In the backup policy, turn on **Back up allowed folders outside stacks**.

System folders such as `/proc` or `/dev`, and Docker's own data folder, are
never backed up.

## Restore

Open the stack or volume and its **Backups** tab:

- **Restore all** puts back everything from a backup: for a stack, its
  folder and all its volumes. Type the name to confirm and press **Replace
  everything**. Leave **Deploy … afterwards** on to start the stack again
  with the restored files.
- **Choose files** restores only the files or folders you pick. A folder
  you pick is made exactly like it was in the backup: newer files in it are
  removed.

Containers that use the data are stopped during the restore and started
again afterwards. The data is restored next to the original first, so a
failed restore leaves the original as it was.

## Recover Docker Manager

If you lost the manager, you can bring it back from a backup of the manager
state. You need the repository's details and your **Recovery Key**.

1. Install Docker Manager again as in the [Quickstart](/quickstart).
   If the backup is in a local folder, mount and allow that folder on the
   new manager first (see [Allow a local folder](#allow-a-local-folder)).
2. On the setup page, press **Import from backup** instead of creating an
   account.
3. Enter where the backups are and your **Recovery Key**, and press **Check
   access**.
4. Press **Show backups**, pick one and press **Next**.
5. Tick **Replace this manager's state with the backup and restart** and
   press **Import and restart**.
6. Sign in with your old owner account.

Then [re-attach](/environments#re-attach-an-environment) each
environment, and create new [API tokens](/api-tokens): the old ones
were revoked.

## Allow a local folder

Docker Manager only writes to folders you allow. Mount the folder at the
same path into the container that writes it, and list it in a setting. For
example, for `/srv/backups` on the manager's server:

```yaml title="compose.yaml"
services:
  docker-manager:
    environment:
      # ...keep the existing lines...
      DOCKER_MANAGER_BACKUP_LOCAL_ROOTS: /srv/backups
    volumes:
      # ...keep the existing lines...
      - /srv/backups:/srv/backups

  docker-agent:
    environment:
      # ...keep the existing lines...
      DOCKER_AGENT_BACKUP_LOCAL_ROOTS: /srv/backups
    volumes:
      # ...keep the existing lines...
      - /srv/backups:/srv/backups
```

The manager writes the manager state; the agent writes the stacks and
volumes of its server. Use a separate folder for each repository, for
example `/srv/backups/manager` and `/srv/backups/apps`.
