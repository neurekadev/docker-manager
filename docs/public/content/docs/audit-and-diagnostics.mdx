## Audit log

**Settings → Audit log** records every sign-in, permission change and
action, with who did it, when, from where and the result. Records can't be
changed or deleted by anyone.

- Filter by **Who**, **Outcome**, **Category** and **When**. **More
  filters** adds environment, dates, actions and resources.
- Open a record to see its details and **What changed**.
- **Export CSV** and **Export NDJSON** download the records that match your
  filters.

Records are kept for 365 days, and at most 1 GB of them; the oldest are
removed first. Reading and exporting the audit log each need their own
permission.

A stack's **Activity** tab shows the audit records and jobs of just that
stack.

## Diagnostics

**Settings → Diagnostics** is for the owner.

**Download support bundle** creates a file you can share when you ask for
help. It holds versions, the settings in use, the state of each server and
its agent, a summary of jobs and the database, and the latest log lines. It
never holds passwords, tokens or file contents, but it does hold server
names and IP addresses.

## Monitoring with Prometheus

Docker Manager can report its own health (job queue, agent connections,
database size and more) to Prometheus.

1. Add `DOCKER_MANAGER_METRICS_ENABLED: "true"` to the manager in your
   `compose.yaml` and run `docker compose up -d` (see
   [Configuration](/docs/configuration)).
2. Create an [API token](/docs/api-tokens) that may only **Scrape internal
   metrics**.
3. Scrape `https://docker.example.com/api/v1/system/metrics` (with your
   address) using that token.

**Settings → Diagnostics** shows these steps with your address.
