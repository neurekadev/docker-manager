---
title: Updates
description: Find newer images for your apps and update them, by hand or on a schedule.
---

A tag such as `nginx:1.27` or `postgres:16` can point to a newer image
after a while. Docker Manager checks whether the image behind a tag changed
and updates the containers that use it. A check only asks the registry; it
never downloads or changes anything.

To update one stack now, choose **Pull & Deploy** in the menu next to its
**Deploy** button.

## Update policies

An **update policy** checks for newer images, and can apply them, on a
schedule. Each server can have one update policy.

1. Open **Updates** and press **Create Update Policy**.
2. Enter a **Name** and choose the **Environments**.
3. Choose what it covers: every stack and the containers Docker Manager
   created. Untick what to leave out.
4. Turn on the schedules you want:
   - **Check Automatically**: when to look for newer images.
   - **Update Automatically**: when to apply what the last check found.
     Containers then restart without asking.

Under **Update Window and Health Wait** you can limit scheduled updates to
certain days and hours, and set how long to wait for an updated container
to become healthy (2 minutes by default).

## Check and apply by hand

The **Updates** page lists the stacks and containers with a newer image, or
a failed check or update. **Preview Update** in a row shows the services
that would be recreated and the new image versions; press **Update …
Services** to run it.

On a policy's page, **Check Now** checks right away, and **Preview Updates
→ Apply Updates** updates everything the policy found.

In the container list and a stack's services, an icon next to each image
shows **Update available**, **Up to date** or a failed check. Click it to
check again.

## Good to know

- Only services whose image really changed are recreated.
- A stack with **Undeployed Changes** is not updated. Deploy or undo the
  changes first.
- There is no automatic rollback. A failed new image is set aside so it is
  not tried again. To go back, pin the previous version in `compose.yaml`
  and deploy.
- Never updated: images pinned to a digest (`image@sha256:…`) or without a
  tag, services that build their own image or set a `pull_policy` other
  than `missing`, and containers with the label
  `docker-manager.update.exclude=true`.
