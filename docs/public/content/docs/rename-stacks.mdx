---
title: Rename a stack
description: Give a stack a new name, with its containers, volumes and folder.
---

A stack's name is its Compose project name. It is part of the names of its
containers, volumes and folder.

1. Open the stack and press the pencil button next to its name.
2. The name turns into a **Stack name** field. Type the new name.
3. Press <kbd>Enter</kbd> or the check mark. To keep the old name, press
   <kbd>Esc</kbd> or the ✕ instead.

<Callout type="warn">
  The rename starts right away, without asking again. The stack stops and
  starts again under the new name, so its services are briefly down.
</Callout>

Docker Manager then:

1. stops the stack,
2. moves its folder and its volumes to the new name (the data comes along),
3. recreates containers outside the stack that use those volumes, with the
   new volume names,
4. starts the stack again under the new name.

While the rename runs, the stack's buttons are turned off, and a badge next
to its name says it is being renamed.

Good to know:

- The field edits the project name, even when the stack shows a different
  display name. To change the name shown in lists, use **Edit details**.
- If a name can't be used (for example, another stack has it), the reason
  shows under the field and nothing changes.
- If the stack's `compose.yaml` sets `name:` at the top, change `name:` in
  the file first, then rename the stack to exactly that name. Until you
  rename the stack, **Deploy** is refused, so the stack never starts again
  with empty volumes.
- If you may not stop and remove a container outside the stack that uses
  its volumes, the rename is refused.
- If something fails early, everything goes back to how it was. If it fails
  late, the stack already has its new name: press **Deploy** to finish.
- The stack's history, revisions, policies and permissions stay with it.

To move a stack to another server instead, see [Migration](/docs/migration).
