## First checks

On the manager's server, in the folder with Docker Manager's
`compose.yaml` (`/opt/docker-manager`, or
`/var/lib/docker/volumes/docker-manager_stacks/_data/docker-manager` once
Docker Manager [manages its own stack](/quickstart#upgrade)):

```bash
docker compose ps
docker compose logs --tail 200 docker-manager docker-agent
```

On another server, check its agent the same way, or with
`docker logs docker-agent` if you used the single command. For more
detail, set the log level to `debug` (see
[Configuration](/configuration)).

When you ask for help, the owner can download a support bundle under
**Settings → Diagnostics**. It never holds passwords, tokens or file
contents, but it does hold server names and recent log lines.

## Setup says the page was not opened over HTTPS

- Open your `https://` address, not `http://server:8080`.
- The address must match `DOCKER_MANAGER_PUBLIC_URL` exactly.
- Docker Manager can't see that your proxy used HTTPS. Add the proxy's IP
  address to `DOCKER_MANAGER_TRUSTED_PROXIES` in `.env` and run
  `docker compose up -d`.

## A server stays offline

Check the agent's log on that server. Usual causes:

- `DOCKER_AGENT_MANAGER_URL` is wrong. It must be your `https://` address.
- The agent doesn't trust your certificate (see
  [Your own certificate authority](/configuration#your-own-certificate-authority)).
- The install command was used already or expired. Create a new one.

## Docker is already connected through another agent

The server already has an agent in Docker Manager. To replace it, choose
**Remove Agent** on the environment's **Agents** tab, then
[re-attach](/environments#re-attach-an-environment) it. Don't use **Add
Environment** for a server Docker Manager already knows.

## Stack actions are refused because of the storage layout

The agent's mount of Docker's volume folder is missing or wrong
(`storage_mount_missing` or `storage_path_mismatch`). Keep the agent's
volume lines exactly as in the Quickstart, or see
[Docker's data folder](/configuration#dockers-data-folder).

## Docker Manager can't read a server's disks

The **Disk Health** card on the server's **System** tab says **Docker
Manager can’t read this server’s disks.** The agent runs without
`privileged: true`, so it can't open the disks. Add the line to the agent
and deploy it again (see
[Monitoring](/monitoring#give-the-agent-access-to-the-disks)). A disk you
connected after the agent started appears once the agent restarts.

## Live views stop updating after about a minute

Your proxy cuts idle connections too early or holds back responses. Allow
idle connections of at least 60 seconds and turn off response buffering.
In Traefik, set the entry point's `readTimeout` to `0s`.

## Uploads fail

Your proxy limits the size of uploads. Raise its limit, for example
`client_max_body_size` in nginx.

## "Too many Docker Manager tabs are open"

One account can have 32 live connections, one per open tab. Close tabs you
no longer need.

## An action on a Docker Manager container is refused

Docker Manager never stops or removes its own containers, data or images.

## A job ended as interrupted

The manager or agent restarted during the job. Check the result, then start
it again. Failed deploys, image pulls and update checks have **Try Again**
on their job page.

## An update is refused because of undeployed changes

The stack's files changed but were not deployed (`update_source_drift`).
Deploy or undo the changes first (see [Stacks](/stacks#revisions)).

## A backup fails because the repository is locked

Another backup, restore or cleanup is using the same repository
(`repository_locked`). Run it again later, or move the backup schedule
away from other jobs on the same repository.

## Importing a backup says the key is wrong

The Recovery Key is wrong, or it was changed after that backup
(`backup_import_key_rejected` or `backup_import_key_rotated`). Enter the older key under **Previous
Recovery Key** too.

## A test message fails

The message names the cause; the channel's **Failing** status shows it
again. Usual fixes:

- **Could not connect** or **the server name could not be found**: the
  service must be reachable from the manager's server. Check the host,
  the port and its firewall.
- **The secure connection failed**: for email, match **Port** and
  **Encryption** (587 with **Explicit TLS (STARTTLS)**, 465 with
  **Implicit TLS**); a self-signed certificate is refused.
- **Refused the credentials** or **rejected the message**: press **Edit →
  Show Address** and check the token, password, webhook URL, chat, topic
  or recipients. A webhook deleted in Discord or Slack needs a new URL.
- **Redirected to another address**: enter the address the service
  redirects to.
- **A test message was just sent**: wait a few seconds and try again.

## Passkeys stopped working after changing the address

Passkeys belong to one address. Sign in with your password and
authenticator code (or a recovery code) and add the passkey again under
**Profile**.

## Moving Docker Manager: the new server waits for the old one

The status page on the new server says **The old server does not answer**.
From the new server, `http://<old server's address>:8080` must open Docker
Manager; check the address and the old server's firewall. If it says **This
Docker Manager is older than the old one**, use the old server's image
version on the new server.

## Locked out of the owner account

On the manager's server, in the folder with Docker Manager's
`compose.yaml` (see [First checks](#first-checks)), run:

```bash
docker compose exec docker-manager docker-manager owner-recovery
```

It prints a link that works once, for one hour. Open it and set a new
password, then set up two-factor sign-in again.

## An upgrade failed

Before an upgrade changes its database, the manager saves a copy. If the
manager doesn't start after an upgrade, go back. Run these in the folder
with Docker Manager's `compose.yaml` (see [First checks](#first-checks)):

1. Stop it and list the saved copies:

   ```bash
   docker compose stop docker-manager
   docker compose run --rm --no-deps docker-manager snapshots list
   ```

2. Restore the newest one:

   ```bash
   docker compose run --rm --no-deps docker-manager snapshots restore <file name>
   ```

3. In `compose.yaml`, set `image:` of `docker-manager` to the version you
   had before and run `docker compose up -d docker-manager`.

Anything you did after the upgrade is lost.
