title: Stacks
description: Create, deploy, edit and import your Compose apps.
---

A **stack** is a Compose app: a `compose.yaml`, an optional `.env` and any
other files the app needs. Docker Manager keeps each stack in its own
folder on its server and runs exactly what the files say.

## Create a stack

1. Open **Stacks** and press **Create stack**.
2. Pick the **Environment** (only when you have more than one).
3. Enter a **Name**, for example `photos`: up to 63 lowercase letters,
   digits, `-` and `_`, starting with a letter or digit.
4. Write or paste your **Compose file**, and a **.env file** if you use one.
5. Press **Validate**, then **Create and deploy**.

To only save the stack, turn off **Deploy after creating** first. To start
from a saved app, use **Create stack ▾ → Create stack from template** (see
[Templates](/templates)).

Docker Manager never overwrites anything: if a folder or Compose project
with that name already exists, it tells you and suggests importing it.

## The stack page

- **Overview**: status, CPU, memory and the stack's services with their
  containers, images, volumes, networks and ports. Each service row can
  start, restart or stop that service, or open its logs or a terminal.
- **Files**: the stack's folder (see [File Manager](/file-manager)).
- **Logs** and **Terminal**: see [Logs](/logs) and
  [Terminal](/terminal).
- **Revisions**: every version of the Compose files.
- **Backups**, **Policies** and **Activity**: its backups, the policies
  that cover it, and its jobs and audit records.

## Deploy, start and stop

**Deploy** makes the server run what your files say. Only services whose
settings changed are recreated. The menu next to it has:

- **Pull & Deploy**: downloads every image of the stack first, so services
  get newer images.
- **Cleanup Orphans & Deploy**: also removes containers of services you
  deleted from `compose.yaml`. Volumes and files are kept.
- **Build & Deploy** (stacks with a `build:` section): builds those images
  first.

A failed deploy is not rolled back. Fix the files, or restore the last good
[revision](#revisions), and deploy again.

The next button shows **Stop** while the stack runs and **Start** when it's
stopped. Its menu has **Start**, **Restart** and **Stop**. **Stop** asks
first and keeps the containers.

**More stack actions → Delete** removes the stack from Docker Manager and
the server. Type its name to confirm. Its volumes are kept unless you tick
**Also remove the stack’s volumes**. Its folder is always kept.

## Edit the files

Open **Files**, change `compose.yaml` or `.env` and press **Save**
(<kbd>Ctrl</kbd> <kbd>S</kbd>). Docker Manager checks the file first and
refuses a change that would break the stack. Saving does **not** deploy: the
stack shows **Undeployed changes** until you press **Deploy**.

## Revisions

Every saved change to the Compose files is a **revision**. The
**Revisions** tab shows who made each one and whether it was deployed.
Pick two and press **Show changes** to compare them.

- With undeployed changes, choose **Deploy these changes** or **Restore
  deployed revision** to undo them.
- To go back to an older version, open its menu and choose **Restore to
  disk**, then **Deploy**.

## Import a project

Docker Manager can take over Compose projects you already run, with their
names, volumes and data.

1. Open **Stacks** and press **Import project**.
2. Pick the **Environment** (only when you have more than one). The list
   shows the projects Docker Manager doesn't manage yet.
3. Press **Import** next to a project.

If the project's files are in a folder Docker Manager manages, it is taken
over where it is and nothing restarts. Otherwise its folder is copied. If
the project runs, Docker Manager asks you to **Stop and import**: it stops
the project, copies and checks its folder, and starts it again from the
copy. If the copy fails, the project starts again from its original folder.
Your original folder is never changed.

To copy a project, the agent must be able to read its folder. If a row
says **Why and how to fix it**, mount the folder into the agent below
`/import` (read-only is enough), then run `docker compose up -d`:

```yaml title="compose.yaml"
services:
  docker-agent:
    volumes:
      # ...keep the existing lines...
      - /opt/stacks:/import/stacks:ro
```

To keep projects where they are instead of copying them, mount the folder
at the **same path** and list it in `DOCKER_AGENT_STACK_ROOTS`:

```yaml title="compose.yaml"
services:
  docker-agent:
    environment:
      # ...keep the existing lines...
      DOCKER_AGENT_STACK_ROOTS: /opt/stacks
    volumes:
      # ...keep the existing lines...
      - /opt/stacks:/opt/stacks
```

Good to know:

- Projects without containers (never started, or taken down) are found by
  their Compose file in a folder Docker Manager manages or below `/import`,
  and show **No containers**. Importing one adds it as **Not deployed**.
- Copying a project is refused when its running containers don't match its
  files. Redeploy the project in the old tool first.
- After the import, stop the old tool from managing the project.

## Rename a stack

Press the pencil next to the stack's name, type the new name and press
<kbd>Enter</kbd>. The stack stops, its folder and volumes move to the new
name with their data, and what was running starts again. Its history and
policies stay with it.

<Callout type="warn">
  The rename starts right away, and the stack is briefly down.
</Callout>

If `compose.yaml` sets `name:` at the top, change it there first, then
rename the stack to exactly that name. To change only the name shown in
lists, use **More stack actions → Edit details**. There you can also add a
description and up to 10 **Links**, for example to the app's website.

## Docker Manager's own stack

If you import Docker Manager's own project, **Deploy** and **Pull &
Deploy** work, so you can upgrade Docker Manager from the app. Restart,
Stop, Migrate, Rename and Delete are off for it.
