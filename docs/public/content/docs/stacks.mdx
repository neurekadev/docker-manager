---
title: Stacks
description: Create, deploy, edit, import and export your Compose apps.
---

A **stack** is a Compose app: a `compose.yaml`, an optional `.env` and any
other files the app needs. Docker Manager keeps each stack in its own
folder on its server and runs exactly what the files say.

## Create a stack

1. Open **Stacks** and press **Create Stack**.
2. Pick the **Environment** (only when you have more than one).
3. Enter a **Name**, for example `photos`: up to 63 lowercase letters,
   digits, `-` and `_`, starting with a letter or digit.
4. Write or paste your **Compose File**, and a **.env File** if you use one.
5. Press **Validate**, then **Create and Deploy**.

To only save the stack, turn off **Deploy After Creating** first. To start
from a saved app, use **Create Stack ▾ → Create Stack From Template** (see
[Templates](/templates)).

Docker Manager never overwrites anything: if a folder or Compose project
with that name already exists, it tells you and suggests importing it.

## The stack page

- **Overview**: status, CPU, memory and the stack's services with their
  containers, images, volumes, networks and ports. Each service row can
  start, restart, stop or force recreate that service, or open its logs or
  a terminal.
- **Files**: the stack's folder (see [File Manager](/file-manager)).
- **Logs** and **Terminal**: see [Logs](/logs) and
  [Terminal](/terminal).
- **Revisions**: every version of the Compose files.
- **Backups**, **Policies** and **Activity**: its backups, whether
  updates and backups cover it, and its jobs and audit records.

## Deploy, start and stop

**Deploy** makes the server run what your files say. Only services whose
settings changed are recreated. The menu next to it has:

- **Pull and Deploy**: downloads every image of the stack first, so services
  get newer images.
- **Pull**: only downloads the images; the next deploy runs them.
- **Force Recreate**: replaces every container with a new one, even if
  nothing changed. It asks first. Volumes and files are kept, but changes
  made inside a container outside its volumes are lost.
- **Remove Orphans and Deploy**: removes the containers of services you
  deleted from `compose.yaml` and deploys. It asks first. Volumes and files
  are kept.

A stack whose saved Compose file has a `build:` section also has a
**Build** button. Its menu has:

- **Build**: builds the images from the base images already on the server,
  without deploying.
- **Pull and Build**: downloads newer base images first, then builds.
- **Build and Deploy**: builds, then deploys.
- **Pull, Build and Deploy**: downloads every image and newer base images,
  builds, then deploys.

While a build runs, its progress shows the current step, such as
**Step 2/5**. **Show Output** opens the full build output.

A failed deploy is not rolled back. Fix the files, or restore the last good
[revision](#revisions), and deploy again.

The next button shows **Stop** while the stack runs and **Start** when it's
stopped. Its menu has **Start**, **Restart** and **Stop**. **Stop** asks
first, then stops and removes the stack's containers and networks, like
`docker compose down`. The stack shows **Stopped**. **Start** brings it up
again from the files of its last deploy, like `docker compose up`. If you
changed the files since, **Start** is off: **Deploy** starts the stack
with them. Named volumes, images and files are kept. Anonymous volumes are
left behind, as with `docker compose down`: the next start or deploy
creates new, empty ones.

A service's **Stop**, in its row on the **Overview**, only stops that
service's containers.

**More Stack Actions → Delete** removes the stack from Docker Manager and
the server. Type its name to confirm. Its volumes are kept unless you tick
**Also Remove the Stack’s Volumes**, shown when you may also remove the
stack's volumes (**Remove Volumes** permission). Its folder is always kept.

## Edit the files

Open **Files**, change `compose.yaml` or `.env` and press **Save**
(<kbd>Ctrl</kbd> <kbd>S</kbd>). Docker Manager checks the file first and
refuses a change that would break the stack. Saving does **not** deploy: the
stack shows **Undeployed Changes** until you press **Deploy**.

Files that `compose.yaml` pulls in with `include` or `extends` belong to the
stack too: they are kept in its revisions and need the same permissions as
`compose.yaml`. They must be inside the stack's folder: a stack that
includes or extends a file from anywhere else doesn't deploy. Saving one of
these files isn't checked; the next deploy shows any mistake.

## Revisions

Every saved change to the Compose files is a **revision**. The
**Revisions** tab shows who made each one and whether it was deployed.
Pick two and press **Show Changes** to compare them.

- With undeployed changes, choose **Deploy These Changes** or **Restore
  Deployed Revision** to undo them.
- To go back to an older version, open its menu and choose **Restore to
  Disk**, then **Deploy**.

## Import a project

Docker Manager can take over Compose projects you already run, with their
names, volumes and data.

1. Open **Stacks** and press **Import Project**.
2. Pick the **Environment** (only when you have more than one). The list
   shows the projects Docker Manager doesn't manage yet.
3. Press **Import** next to a project.

If the project's files are in a folder Docker Manager manages, it is taken
over where it is and nothing restarts. Otherwise its folder is copied. If
the project runs, Docker Manager asks you to **Stop and Import**: it stops
the project, copies and checks its folder, and starts it again from the
copy. If the copy fails, the project starts again from its original folder.
Your original folder is never changed.

To copy a project, the agent must be able to read its folder. If a row
says **Why and How to Fix It**, mount the folder into the agent below
`/import` (read-only is enough), then run `docker compose up -d`:

```yaml title="compose.yaml"
services:
  docker-agent:
    volumes:
      # ...keep the existing lines...
      - /opt/stacks:/import/stacks:ro
```

To keep projects where they are instead of copying them, mount the folder
at the **same path** and list it in `DOCKER_AGENT_STACK_ROOTS`:

```yaml title="compose.yaml"
services:
  docker-agent:
    environment:
      # ...keep the existing lines...
      DOCKER_AGENT_STACK_ROOTS: /opt/stacks
    volumes:
      # ...keep the existing lines...
      - /opt/stacks:/opt/stacks
```

Good to know:

- Projects without containers (never started, or stopped with
  `docker compose down`) are found by their Compose file in a folder
  Docker Manager manages or below `/import`,
  and show **No Containers**. Importing one adds it as **Not Deployed**.
- Copying a project is refused when its running containers don't match its
  files. Redeploy the project in the old tool first.
- After the import, stop the old tool from managing the project.

## Export a stack as an archive

An archive is one file with the stack's folder and the data of its
volumes. Use it to keep a copy, or to create the stack on another server
or another Docker Manager.

1. On the stack's page, open **More Stack Actions → Export Archive**.
2. Check the list of volumes. Clear **Include** for any volume you don't
   want in the archive.
3. Press **Export Archive**.

The stack stops while the archive is written, then starts again. The
download starts when the export is done. If you closed the dialog, open
**Export Archive** again and press **Download Archive**.

<Callout type="warn">
  The archive holds your `.env` values and your volumes' data. Keep it
  somewhere safe.
</Callout>

## Create a stack from an archive

1. Open **Stacks** and choose **Create Stack ▾ → Create Stack From Archive**.
2. Press **Choose Archive** and pick the file, or drop the file there.
3. Pick the **Environment** (only when you have more than one).
4. Keep the **Name** or enter a new one. Volumes named after the stack get
   the new name too.
5. Press **Create Stack**, then **Open Stack**.

Docker Manager checks the environment before it writes anything, and lists
what must be fixed, for example a name, folder, volume or port already in
use there. To only create the stack, turn off **Deploy After Creating**.

Good to know:

- Archives stay on the manager for one day, then they are removed.
- Archives can be up to 10 GB. Change the limit with
  `DOCKER_MANAGER_STACK_ARCHIVE_MAX_MB` (see [Configuration](/configuration)).
- Only plain local volumes are in the archive. Not in it: external
  volumes, volumes with driver options or another driver, anonymous
  volumes, folders mounted from outside the stack's folder, and images. The
  dialog lists what is left out. Images are pulled or built when the stack
  is deployed.
- If `compose.yaml` sets `name:` at the top, the new stack must use that
  name.

## Rename a stack

Press the pencil next to the stack's name, type the new name and press
<kbd>Enter</kbd>. The stack stops, its folder and volumes move to the new
name with their data, and what was running starts again. Its history stays
with it.

<Callout type="warn">
  The rename starts right away, and the stack is briefly down.
</Callout>

If `compose.yaml` sets `name:` at the top, change it there first, then
rename the stack to exactly that name. To change only the name shown in
lists, use **More Stack Actions → Edit Details**. There you can also add a
description and up to 10 **Links**, for example to the app's website.
Drag a link by its handle, or use the arrow keys on it, to change the
order.

## Docker Manager's own stack

If you import Docker Manager's own project, **Deploy**, **Pull and Deploy**
and **Force Recreate** work, so you can upgrade Docker Manager from the
app. Restart, Stop, Migrate, Export Archive, Rename and Delete are off for
it.
