---
title: Import existing projects
description: Take over the Compose projects you already run on a server.
---

Already running apps with Docker Compose, by hand or with another tool?
Docker Manager can take them over, with their names, volumes and data.

## Import a project

1. Open **Stacks** and press **Import project**.
2. Pick the server. The list shows the Compose projects on it that Docker
   Manager does not manage yet, running or stopped. A project needs at
   least one container: a project you took down with `docker compose down`
   doesn't appear. Start it once, or paste its Compose file into
   **Stacks → Create stack** instead.
3. Press **Import** next to a project.

What happens next depends on where the project's files are:

- **The files are already in a folder Docker Manager manages.** The project
  is taken over where it is. Nothing restarts.
- **The files are somewhere else.** Docker Manager copies the project into
  its own folder:
  1. it stops the project (it asks you first; press **Stop and import**),
  2. copies its whole folder, including data folders next to the Compose
     file, with owners and permissions,
  3. checks the copy,
  4. starts the project again from the copy, with the same name and
     volumes.
- **Docker Manager's own project** is copied while it keeps running.
  Docker Manager moves onto the copy the next time you deploy that stack.

If something goes wrong before the containers are recreated, the copy is
removed and the project starts again from its original folder.

Projects Docker Manager already manages are hidden. Turn off **Hide managed
stacks** to see them.

## Let the agent read the project

To copy a project, the agent must be able to read its folder. When a
project can't be imported, its row has **Why and how to fix it**. Most
often the agent can't reach the folder: mount it into the agent **below
`/import`**. Read-only is enough.

On the manager's server, add a line to the agent in your `compose.yaml`:

```yaml title="compose.yaml"
  docker-agent:
    volumes:
      # ...keep the existing lines...
      - /opt/stacks:/import:ro
```

Then run `docker compose up -d`. Several folders work too, for example
`/srv/apps:/import/apps:ro`.

Tools such as Arcane, Dockge or Portainer run Compose inside their own
container. Mount the folder where the tool keeps its projects, for example:

```yaml
      - /var/lib/docker/volumes/arcane_data/_data/projects:/import:ro
```

Remove the `/import` line again when you are done importing.

## Manage projects where they are

If you want to keep your projects in a folder such as `/opt/stacks`, you can
let Docker Manager manage them there instead of copying them. Mount the
folder at the **same path** and list it in `DOCKER_AGENT_STACK_ROOTS`:

```yaml title="compose.yaml"
  docker-agent:
    environment:
      # ...keep the existing lines...
      DOCKER_AGENT_STACK_ROOTS: /opt/stacks
    volumes:
      # ...keep the existing lines...
      - /opt/stacks:/opt/stacks
```

Projects in that folder are then taken over in place when you import them.

## Good to know

- An import is refused when the running containers use settings that are
  not in the project's files. Usually the files were edited in the other
  tool but not redeployed. Redeploy the project there first, then import
  again. If the other tool keeps variables in its own database, put them
  into the project's `.env` and try again.
- In the project's files, write full paths instead of `~` (for example
  `/root/.config/app` instead of `~/.config/app`). `~` means a different
  folder for each tool.
- Your original folder is never changed. Once the stack runs well, delete
  the original yourself, and stop the old tool from managing the project so
  it does not redeploy or remove it.
