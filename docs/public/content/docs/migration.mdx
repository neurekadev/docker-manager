---
title: Migration
description: Move a stack, a volume, everything on a server, or Docker Manager itself to another server.
---

Migration moves your apps and their data from one server to another. It
needs at least two environments (an *environment* is one server with its
agent, see [Add more servers](/docs/add-hosts)).

Every migration is checked first: Docker Manager lists what must be fixed
before anything stops. Every copy is verified end to end, and nothing on
the old server is deleted until you say so.

## What you can move

| You move | What comes along | What stays behind |
| --- | --- | --- |
| **A stack** | Its folder with `compose.yaml`, `.env` and the files next to them. Its named volumes with all their data. Its history, revisions, display name, update and backup policies, and the permissions given for the stack or its services. | Folders it mounts from outside its own folder, host devices, the data of volumes with a special driver or driver options (for example NFS), and permissions given for the whole environment. |
| **A volume** | A copy of its data, under the same or a new name. | The volume itself: the original is not changed. |
| **A whole environment** | Every stack, as above, moved group by group. Networks you made by hand that the stacks join are created on the new server first. | Docker Manager's own stack, containers that are not part of a stack, and volumes no stack uses. |
| **Docker Manager itself** | Docker Manager with everything in it (users, sign-ins, settings, API tokens, templates, history, connected servers), plus every stack on its server. | The same as for a whole environment. |

Images come along in the easiest way: images from a registry are
downloaded again on the new server, images with a `build:` section are
built there, and images you built or loaded by hand are copied.

## Move a stack

Open the stack and choose **More stack actions → Migrate**.

1. **Destination**: pick the server and press **Check destination**.
2. **Check**: Docker Manager lists what must be fixed first and what will
   be copied.
   - **Copy data**: untick it for a volume that should start empty on the
     new server. Anonymous volumes are not copied unless you tick them.
   - **Copy image**: tick it to copy an image from the old server instead
     of downloading it again.
3. **Confirm**: tick **I understand that … is unavailable during the
   migration** and press **Start migration**.
4. **Move**: the stack stops, its folder and volumes are copied, and it
   starts on the new server.

If anything fails, the stack goes back to the old server and starts there.

## Move a volume

Open a volume and its **Migrate** tab.

1. **Destination**: pick the **Destination environment** and a **Name on
   the destination**.
2. **Check**: Docker Manager checks the copy can go ahead. If running
   containers use the volume, you can tick **Copy while the containers keep
   running**. The copy may then be slightly out of step, like a copy of a
   running database.
3. Press **Migrate volume**.

## Move a whole environment

Use this to move to a new server, or to empty a server before you retire
it. Open the environment and choose **More actions → Migrate environment**.

1. **Destination**: pick the new server. All stacks are ticked; untick the
   ones that should stay.
2. **Check**: Docker Manager checks every stack at once and shows:
   - what must be fixed first,
   - the **Order**: stacks that share a network or a volume (for example a
     reverse proxy and the apps behind it) form a group. A group stops
     together and moves in order, the stack that creates the network
     first, so the apps find their proxy when they start,
   - the networks it creates on the new server first,
   - what is **Not moved**, and why.
3. **Confirm**: tick **I understand that each group's stacks are
   unavailable while it moves** and press **Start migration**.
4. **Move**: the groups move one after the other. The other groups keep
   running on the old server until it is their turn.

If a stack can't be moved, the migration stops there. That stack and the
rest of its group start again on the old server. Stacks that already moved
stay on the new server. Fix the problem and press **Migrate the rest**.

You can leave the page while the stacks move. When you come back to
**Migrate environment**, it shows the last migration and what each stack
did, until nothing is left to do: the old copies are removed and no stack
of it waits on the old server. To begin again from the first step, press
**Start a new migration**.

## Move Docker Manager to a new server

Use this when you replace the server Docker Manager runs on. Your apps on
that server move along, and your other servers stay connected. Nobody has
to sign up again or reconnect a server by hand.

You do three things:

1. **Set up the new server.** Open **Settings → Move to a new server**.
   Enter **This server's address** and **New server's address** (their IP
   addresses or host names on your network) and press **Create setup
   files**. Save the `compose.yaml` and `.env` it shows in an empty folder
   on the new server and run:

   ```bash
   docker compose up -d
   ```

   Or copy the command under **Or paste this on the new server** and paste
   it into a terminal on the new server. It creates a `docker-manager`
   folder with both files and starts Docker Manager for you.

   The page ticks off **New server's agent connected** and **New Docker
   Manager is waiting** by itself. Then press **Next**.
2. **Check and move.** The **Check** step shows what moves, what must be
   fixed first and how long each group of apps is down. Read **Before you
   start**, then press **Move everything** on the **Move** step. Your apps
   move group by group; then Docker Manager hands itself over to the new
   server.
3. **Point DNS at the new server.** When the page says **Docker Manager
   moved.**, point your Docker Manager address (and your apps' addresses)
   at the new server. Then sign in as usual.

Your usual address stops working while your reverse proxy moves, until
DNS points at the new server. Follow the move meanwhile on the new
server's status page, **Moving Docker Manager here**, at
`http://<new server's address>:8080`. It needs no sign-in.

After you sign in on the new server, the **Move complete** card on the
dashboard offers **Remove old copies from …** and **Open … to archive it**
for the old server.

<Callout type="warn">
  The setup files are shown once and contain a pairing code. Keep them
  private. If you lose them, or they expire before the new server's agent
  connects (after 24 hours), press **Create new setup files** on the **New
  server** step. The old files stop working: put the new `.env` in the
  same folder on the new server and run `docker compose up -d` again.
</Callout>

Good to know:

- Until you press **Move everything**, nothing changes and you can
  **Cancel the move**. If an app can't move, the move stops before
  Docker Manager is handed over: fix the problem and press **Try again**.
  Apps that already moved stay on the new server.
- While Docker Manager hands over, nothing can be changed. A banner says
  so. Running tasks finish first.
- If your browser saves the downloaded `.env` without its leading dot,
  rename the file to `.env`.
- If your reverse proxy sends Docker Manager's address to the old
  server's IP address, change it to the new server's IP address.
- The two servers talk over plain HTTP on your network. The move is
  encrypted with the pairing code, so that is safe.
- The new server must run the same Docker Manager version as the old one,
  or a newer one.
- After the move you can remove `DOCKER_MANAGER_MOVE_FROM` and
  `DOCKER_MANAGER_MOVE_CODE` from the new server's `.env`.
- If a server was offline during the move, the **Move complete** card
  shows the one line to change in its agent's settings.

## After a move

The old copy stays on the old server, stopped. Check that everything works
on the new server first.

- For one stack, press **Remove from …** to delete the old copy (you must
  type the name to confirm), or **Start again on …** to run it there once
  more.
- After an environment migration, **Remove old copies from …** deletes the
  old copies of all moved stacks at once. You must type the old server's
  name to confirm. Each stack then shows **Old copy removed**.
- While old copies are left, the old server's page reminds you, for
  example "3 stacks moved to NAS. Their old copies are still on this
  server." Press **Review the migration** to see the result and remove
  them.

Removing an old copy deletes its containers, networks, copied volumes and
folder on the old server. Docker Manager never deletes an old copy on its
own. When a server is empty, you can archive it (see
[Environments](/docs/environments)).

Good to know:

- Each group of stacks is down while it moves: from the moment it stops
  until each of its stacks runs on the new server. The check shows how long
  that should take.
- Networks created for you get Docker's default addresses. If a service
  needs a fixed address, create the network on the new server by hand
  before you start.
- Networks other than bridge networks, and volumes a stack joins but no
  stack creates, must already exist on the new server. The check tells you.
- Backups made on the old server stay where they are. A moved stack can
  only be restored from S3 storage (see [Restore](/docs/restore)).
- Traffic between the servers goes through Docker Manager. If an agent
  connects over plain HTTP, the check warns you that the data is not
  encrypted on the way.
