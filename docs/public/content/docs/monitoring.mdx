---
title: Monitoring
description: The health of each server's disks and RAID arrays.
---

Docker Manager watches the disks of every server: their own health
reports (SMART) and their RAID arrays, so you can replace a disk before it
fails. A disk or array with a problem raises an [alert](/alerts). For CPU,
memory, network and disk use over time, see [Metrics](/metrics).

## Check a server's disks

1. Open **Environments**, pick an environment and open its **System** tab.
2. The **Disk health** card lists each disk with its **Health**,
   **Temperature**, how long it has been **Powered on** and its
   **Issues** in words, for example "8 reallocated sectors" or "Worn 92%".
   Serial numbers and firmware are under **Advanced**.
3. Press the info button (ⓘ) at the end of a disk's row to see all its
   SMART data: every attribute with its value, worst, threshold and raw
   value, and the other values the disk reports, such as power cycles or
   data written.
4. Press **Check disks now** to read every disk again right away. The
   agent also reads them every 30 minutes; **Last checked** says when it
   last did.

A disk's health is one of:

- **Healthy**: nothing to do.
- **Warning**: the disk reports damaged or pending sectors, errors, wear
  of 90% or more, or little spare capacity. Keep your backups current and
  plan a replacement.
- **Failing**: the disk's own self-check failed or it reports a critical
  problem. Back up and replace it soon.
- **Sleeping**: the disk was in standby and was not woken; it shows the
  values from its last check. A disk whose last check found a problem
  keeps its **Warning** or **Failing** badge while it sleeps. A disk that
  sleeps through every check is woken for one once a day.
- **Unreadable**: the disk could not be read, didn't answer in time or
  reported no health data; hover the badge to see why.
- **Missing**: the agent found the disk before but no longer does. It may
  have failed or been removed. It stays in the list until the agent
  restarts.

## Check RAID arrays

If the server has Linux software RAID or ZFS pools, the **RAID** card
lists each array, a software RAID array by its path such as `/dev/md0`,
with its state (**Healthy**, **Degraded**, **Rebuilding**, **Checking**,
**Failed** or **Inactive**), its disks (a failed one in red) and the
progress of a rebuild or check with the time left. Press the info button
(ⓘ) to see the array's level, size, metadata, chunk size, layout and
bitmap, and each member with its slot, role and the health of its disk.
Press **Check RAID now** to read it again. A server without arrays
shows **No RAID arrays found** in the **Disk health** card.

## Give the agent access to the disks

To read the disks, the agent runs with `privileged: true`. The
[Quickstart](/quickstart) files and the install commands do this. If the
**Disk health** card says **Docker Manager can’t read this server’s
disks.**, add the line to that server's agent:

1. Open **Stacks** and the server's `docker-manager` stack, then its
   **Files** tab.
2. In `compose.yaml`, add `privileged: true` to the `docker-agent`
   service:

   ```yaml title="compose.yaml"
   services:
     docker-agent:
       # ...keep the existing lines...
       privileged: true
   ```

3. Save the file and press **Deploy**.

If you haven't [imported](/quickstart#upgrade) Docker Manager's project
yet, edit the `compose.yaml` on the server and run `docker compose up -d`
there. An agent started with the single command needs a new container with
`--privileged`.

Good to know:

- Checks only read the disks: they never start a disk self-test or a RAID
  scrub.
- Disks you connect later appear after the agent restarts.
- If the agent can't scan or read the disks or the RAID state, or stops
  reporting them, an [alert](/alerts) says so.
- Virtual disks have no health data; the card says so. btrfs RAID and
  hardware RAID controllers are not covered.
- `DOCKER_AGENT_SMART_INTERVAL` changes how often the agent reads the
  disks, `DOCKER_AGENT_SMART_WAKE_AFTER` how long a sleeping disk may go
  unchecked, and `DOCKER_AGENT_SMART_ENABLED` turns disk checks off (see
  [Configuration](/configuration#agent-settings)).
