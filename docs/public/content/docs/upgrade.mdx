---
title: Upgrade
description: Move to a newer Docker Manager, and go back if something goes wrong.
---

Upgrade the manager first, then the agent on every server. Until versioned
releases exist, upgrade them all together.

## Upgrade

On the manager's server, in the folder with your `compose.yaml`:

```bash
docker compose pull
docker compose up -d
```

This upgrades the manager and the agent next to it. Then, on every other
server, in its agent's folder:

```bash
docker compose pull
docker compose up -d
```

If you started an agent with the single `docker run` command instead,
replace its container. The agent keeps its identity in the
`docker-manager_agent` volume, so it connects again on its own. Use your
own address:

```bash
docker pull code.neureka.dev/docker-manager/docker-agent:edge
docker rm -f docker-agent
docker run -d --name docker-agent --restart unless-stopped \
  -e DOCKER_AGENT_MANAGER_URL='https://docker.example.com' \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v /var/lib/docker/volumes:/var/lib/docker/volumes \
  -v docker-manager_stacks:/var/lib/docker/volumes/docker-manager_stacks/_data \
  -v docker-manager_agent:/var/lib/docker-agent \
  --label docker-manager.role=agent \
  code.neureka.dev/docker-manager/docker-agent:edge
```

In your browser, Docker Manager then shows **A new version of Docker
Manager is available**. Press **Reload to update** when it suits you.

Older setups label Docker Manager's containers with
`dev.neureka.docker-manager.role` instead of `docker-manager.role`. The old
label keeps working, so you don't have to change anything. To switch, rename
the label in your `compose.yaml` (or in your `docker run` command) and start
the containers again as shown above.

### Upgrade from the app

If you imported Docker Manager's own project as a stack (see
[Import existing projects](/docs/import-projects)), you can upgrade it like
any other stack: choose **Pull & Deploy** in its **Deploy** menu, or cover
it with an update policy.
The page reconnects within a minute.

## What happens during an upgrade

Before the manager changes its database for a new version, it saves a copy
of the database (the newest 3 copies are kept). If the upgrade fails, the
manager doesn't start. Restore the saved copy to go back, as shown below.

## Go back after a failed upgrade

1. Stop the manager and list the saved copies:

   ```bash
   docker compose stop docker-manager
   docker compose run --rm --no-deps docker-manager snapshots list
   ```

2. Restore the newest one:

   ```bash
   docker compose run --rm --no-deps docker-manager snapshots restore <file name>
   ```

3. In `compose.yaml`, set `image:` of `docker-manager` to the version you had
   before, for example
   `code.neureka.dev/docker-manager/docker-manager@sha256:<digest>`, and
   start it:

   ```bash
   docker compose up -d docker-manager
   ```

Anything you did after the upgrade is lost.

<Callout title="Note your version before you upgrade">
  To be able to go back, note the image you run now:

  ```bash
  docker image inspect --format '{{index .RepoDigests 0}}' code.neureka.dev/docker-manager/docker-manager:edge
  ```
</Callout>
