---
title: Restore
description: Get a stack, a volume, a file or all of Docker Manager back from a backup.
---

A restore always puts data back where it lives now. Data is first restored
next to the original and then swapped in. If the restore fails, the
original stays as it was.

## Restore a stack or a volume

Open the stack or volume and its **Backups** tab, then:

- **Restore all** puts back everything from a backup. For a stack, that is
  its folder **and** all its volumes. Type the name to confirm and press
  **Replace everything**. **Deploy … afterwards** starts the stack again
  when the restore is done (on by default).
- **Choose files** lets you pick some files or folders from a backup and
  press **Review restore**. A folder you pick is made exactly like it was
  in the backup.

Containers that use the data are stopped during the restore and started
again afterwards.

## More restore options

Open a backup from the **Backups** page and press **Restore** to choose:

- **Stack definition and files**: the stack's folder only. Volumes are not
  touched. Deploy the stack afterwards.
- **Volumes of the stack** (or **The volume**): tick the volumes to put
  back. A volume that no longer exists is created.
- **One file**: a single file.

Press **Review**, check the summary, type the name and press **Restore
now**.

**Stop the containers that use this data while restoring** is on by
default. If you turn it off, a restore into data that running containers
use is refused.

A stack you moved to another server can only be restored from S3 storage.

## Recover Docker Manager itself

If you lost the manager, for example with its server, you can bring it
back from a backup of the manager state. You need the backup location, its
access keys if it is S3, and your **Recovery Key**.

1. Install Docker Manager again as in the [Quickstart](/docs/quickstart),
   with a new, empty data volume.
2. If the backup is in a local folder, mount and allow it on the new
   manager (see [Allow a local folder](/docs/backups#allow-a-local-folder)).
3. Open Docker Manager. On the setup page, press **Import from backup**
   instead of creating an account.
4. Enter where the backups are and your **Recovery Key**. If you changed
   the key recently, enter the old one under **Previous Recovery Key** too.
   Press **Check access**.
5. Press **Show backups**, pick a backup and press **Next**.
6. Tick **Replace this manager's state with the backup and restart** and
   press **Import and restart**.
7. Sign in with your old owner account. Users, stacks, templates and
   settings are back.

Then:

- **Connect your servers again.** For each environment, press
  **Re-attach** on its **Agents** tab and run the command on that server.
  Where the agent still runs from a `compose.yaml`, use the **On the Docker
  Manager host** command in that folder: it hands the new code to the
  running agent. Don't use **Add environment**: that creates a new, empty
  environment.
- **Mount local backup folders at the same paths** as before on each
  server.
- **Create new API tokens.** The old ones were revoked.
