title: Environments

An **environment** is one Docker server with its agent. The
**Environments** page lists them all with their status, Docker and agent
version, containers, CPU and memory. To add one, see
[Add more servers](/quickstart#add-more-servers).

An environment is **Online** while its agent is connected. When it is
**Offline**, you still see its last known state, but actions on it are off
until it reconnects.

## An environment's page

- **Overview**: CPU, memory, disk, uptime, the number of containers,
  images, volumes and networks, and charts from the last hour up to the
  last 90 days.
- **System**: details about the server and its Docker Engine.
- **Agents**: the agent, its version and when it was last seen.
- **Jobs**: the latest jobs on this server.

**Edit** changes the environment's **Name** and its **Service address**:
the host name or IP address you browse to. With an address, published ports
become links.

By default the network chart shows only the agent's own traffic. To see the
whole server's traffic, add `pid: host` to the agent in its `compose.yaml`.
This lets the agent see every process on the server.

## Archive an environment

To stop managing a server, choose **More actions → Archive environment**.
Docker Manager first shows what depends on it. Archiving:

- disconnects the agent for good,
- keeps the stacks, policies, history and backups, so you can bring it
  back,
- removes the permissions given for this environment,
- changes nothing on the server. Remove the agent container there yourself
  if you no longer need it.

To keep its apps under Docker Manager, [migrate](/migrations) them to
another server first. Archived environments are on the **Archived** tab.

## Re-attach an environment

**Re-attach** connects a server again that Docker Manager already knows:
after you archived it, removed its agent or recovered Docker Manager from a
backup.

1. Open the environment and press **Re-attach** (also on its **Agents**
   tab).
2. Press **Create install command** and run the command on that server. For
   the agent next to the manager, use the **On the Docker Manager host**
   tab.

## Manage the agent

On the **Agents** tab, the agent's menu has:

- **Remove agent**: the agent can no longer connect. Type the environment's
  name to confirm. Nothing on the server changes.
- **Rotate credential**: gives the agent a new secret, if you think the old
  one leaked.

Upgrade the manager first, then the agents. An agent one release behind
the manager still works and shows **Upgrade recommended**. An older agent,
or one newer than the manager, is refused until you
[upgrade](/quickstart#upgrade) it.
