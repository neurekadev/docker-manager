---
title: Quickstart
description: Install Docker Manager, connect your first server and add more.
---

This guide installs the manager and an agent on one server. It takes about
ten minutes.

## 1. Create the files

Make a folder for Docker Manager and go into it:

```bash
mkdir -p /opt/docker-manager && cd /opt/docker-manager
```

Create a file named `compose.yaml` with this content:

```yaml title="compose.yaml"
name: docker-manager

services:
  docker-manager:
    image: ghcr.io/neurekadev/docker-manager:edge
    restart: unless-stopped
    ports:
      - "8080:8080"
    environment:
      DOCKER_MANAGER_PUBLIC_URL: ${DOCKER_MANAGER_PUBLIC_URL}
      DOCKER_MANAGER_TRUSTED_PROXIES: ${DOCKER_MANAGER_TRUSTED_PROXIES}
    volumes:
      - data:/var/lib/docker-manager
    labels:
      docker-manager.role: manager
    networks:
      - docker-manager

  docker-agent:
    image: ghcr.io/neurekadev/docker-agent:edge
    restart: unless-stopped
    privileged: true
    depends_on:
      - docker-manager
    environment:
      DOCKER_AGENT_MANAGER_URL: http://docker-manager:8080
      DOCKER_AGENT_MANAGER_ALLOW_HTTP: "true"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
      - /var/lib/docker/volumes:/var/lib/docker/volumes
      - stacks:/var/lib/docker/volumes/docker-manager_stacks/_data
      - agent:/var/lib/docker-agent
      - .:/import/docker-manager:ro
    labels:
      docker-manager.role: agent
    networks:
      - docker-manager

networks:
  docker-manager:
    name: docker-manager

volumes:
  data:
  agent:
  stacks:
```

Then create a file named `.env` next to it:

```bash title=".env"
# The address you will open Docker Manager at. It must start with https://
DOCKER_MANAGER_PUBLIC_URL=https://docker.example.com

# The address of your reverse proxy. This value fits a proxy that runs on
# this server. If your proxy runs on another machine, put that machine's
# IP address here instead, for example 192.168.1.10.
DOCKER_MANAGER_TRUSTED_PROXIES=172.16.0.0/12
```

Replace `docker.example.com` with your own domain name.

<Callout title="Keep these lines as they are">
  The agent needs the Docker socket and Docker's volume folder
  (`/var/lib/docker/volumes`) at the same path inside its container. The
  line with `/import/docker-manager` lets it read this folder, so you can
  [upgrade from the app](#upgrade). `privileged: true` lets it read your
  disks' health (see [Monitoring](/monitoring)). Keep the project name
  `docker-manager` too. If your Docker keeps its data
  somewhere else, see [Configuration](/configuration#dockers-data-folder).
</Callout>

## 2. Start it

```bash
docker compose up -d
docker compose ps
```

After a minute, both containers show as running and `healthy`.

## 3. Put HTTPS in front of it

Docker Manager listens on port `8080` of your server, over plain HTTP. Point
your reverse proxy at it, so that your domain name opens Docker Manager over
HTTPS. If your proxy runs in Docker on this server, you can instead connect
it to the `docker-manager` network and point it at
`http://docker-manager:8080`.

Your proxy must:

- use a certificate your browser trusts,
- speak HTTP/2 to browsers,
- allow WebSocket connections,
- keep idle connections open for at least 60 seconds,
- allow uploads as large as the files you want to upload (1 GB is a good
  start),
- pass on the original host name and forwarded headers. Most proxies do
  this by default.

Once you open Docker Manager over HTTPS, it tells your browser to use only
HTTPS for that address for the next year.

## 4. Create your account

Open your address, for example `https://docker.example.com`.

<Callout type="warn" title="Do this right away">
  The first person who opens a new Docker Manager becomes its owner, and
  the owner can do everything. Create your account as soon as Docker
  Manager is running.
</Callout>

Choose a username and a password of at least 15 characters, then press
**Create Owner Account**. Then add an authenticator app or a passkey under
**Profile** (see [Users & Groups](/users-and-groups#your-account)).

## 5. Connect this server

1. Open **Environments** and press **Add Environment**.
2. Give it a name if you like (without one, the server's name is used), and
   press **Create Install Command**.
3. Open the **On the Docker Manager Host** tab and copy the command.
4. Run it on your server, in the folder with your `compose.yaml`
   (`/opt/docker-manager`).

The page shows **Connected** within a few seconds. Your server now appears
with its containers, images, volumes and networks. Next,
[create your first stack](/stacks).

## Add more servers

Every other server you want to manage needs its own agent. It connects to
your Docker Manager address over HTTPS and needs no open ports.

1. In Docker Manager, open **Environments → Add Environment**, give it a
   name if you like and press **Create Install Command**. The command works
   once and expires after one hour (up to 24 hours under **More Options**).
2. Start the agent in one of two ways:
   - **Single command**: copy the command from the **On Another Docker
     Host** tab and run it on the new server.
   - **Compose**: make a folder such as `/opt/docker-manager` on the new
     server and create the `compose.yaml` below. Copy the lines that start
     with `DOCKER_AGENT_` from the **On Another Docker Host, with Compose**
     tab into a `.env` file next to it, and run `docker compose up -d`.

```yaml title="compose.yaml"
name: docker-manager

services:
  docker-agent:
    image: ghcr.io/neurekadev/docker-agent:edge
    restart: unless-stopped
    privileged: true
    environment:
      DOCKER_AGENT_MANAGER_URL: ${DOCKER_AGENT_MANAGER_URL}
      DOCKER_AGENT_ENROLLMENT_TOKEN: ${DOCKER_AGENT_ENROLLMENT_TOKEN:-}
      DOCKER_AGENT_ENVIRONMENT_NAME: ${DOCKER_AGENT_ENVIRONMENT_NAME:-}
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
      - /var/lib/docker/volumes:/var/lib/docker/volumes
      - stacks:/var/lib/docker/volumes/docker-manager_stacks/_data
      - agent:/var/lib/docker-agent
      - .:/import/docker-manager:ro
    labels:
      docker-manager.role: agent

volumes:
  agent:
  stacks:
```

```bash title=".env"
DOCKER_AGENT_MANAGER_URL=https://docker.example.com
DOCKER_AGENT_ENROLLMENT_TOKEN=dye_...
```

The page shows **Connected** within a few seconds. You can then remove the
`DOCKER_AGENT_ENROLLMENT_TOKEN` line; it works only once anyway. If the
server doesn't connect, see [Troubleshooting](/troubleshooting#a-server-stays-offline).

Good to know:

- One Docker server can have only one agent. To connect a server again that
  Docker Manager already knows, use **Re-Attach** (see
  [Environments](/environments#re-attach-an-environment)).
- For a cloned virtual machine, tick **This Host Is a Clone of a Connected
  Host** under **More Options** before you create the command.
- Unused commands are listed under **Waiting for an Agent** on the
  **Environments** page. **Revoke** cancels one.

## Upgrade

Docker Manager upgrades itself from the app, like any other stack.

1. **Once:** open **Stacks → Import Project**, pick this server and press
   **Import** next to `docker-manager`. It keeps running while it is
   imported.
2. **To upgrade:** open the `docker-manager` stack and choose **Pull &
   Deploy** in the menu next to **Deploy**.
3. The app shows **A new version of Docker Manager is available**. Press
   **Reload to Update**.

If you installed Docker Manager before it showed disk health, add
`privileged: true` to each server's `docker-agent` service so the agent can
read the disks (see
[Monitoring](/monitoring#give-the-agent-access-to-the-disks)).

Backups now go to S3-compatible storage only. If you back up to a local
folder, [add an S3 repository](/backups#1-add-a-repository) before you
upgrade. The upgrade removes local-folder repositories and their backups
from the app; the files stay in the folder. A backup policy that used one
moves to your oldest S3 repository and is turned off, so check it and
turn it on again. Without an S3 repository, such a policy is removed.

Good to know:

- From now on, change Docker Manager's files in the stack's **Files** tab.
  After the first deploy it runs from its copy in
  `/var/lib/docker/volumes/docker-manager_stacks/_data/docker-manager`, and
  `/opt/docker-manager` is no longer used.
- Upgrade the manager first, then your other servers: import each server's
  `docker-manager` project the same way and use **Pull & Deploy** on it.
- To upgrade automatically, keep these stacks covered in the
  [update settings](/updates).
- An agent you started with the single command is not a Compose project,
  so it can't be upgraded from the app. Set it up with Compose instead.
- Before the manager changes its database for a new version, it saves a
  copy. If an upgrade fails, see
  [Troubleshooting](/troubleshooting#an-upgrade-failed).
