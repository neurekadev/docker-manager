Docker Manager is a single pane of glass for all your Docker servers. From
one web page you run your apps, edit their files, upload data, read logs,
open terminals, update images and back everything up. You don't need to SSH
into a server, open a text editor or copy files by hand. One browser tab is
all you need to manage your whole setup, whether you have one server or
many.

## How it works

Docker Manager has two parts:

- The **manager** is the web app. You run it once.
- The **agent** is a small container on every server you manage. It
  connects out to the manager and does the work on its server. It opens no
  ports, so servers need no firewall changes.

Each server with its agent is an **environment**. The environment switcher
at the top of the side menu picks which one the pages show, or **All
environments**.

Longer tasks, such as a deploy or a backup, run as **jobs**. They keep
running when you close the browser. **Jobs** in the menu lists them all.

Backups, update checks, updates and cleanups can run on a **schedule**:
hourly, daily, weekly or with a cron expression, in the time zone you pick.
Nothing runs on its own until you turn its schedule on. **Schedules** in
the menu lists them all.

Press <kbd>Ctrl</kbd> <kbd>K</kbd> (<kbd>⌘</kbd> <kbd>K</kbd> on a Mac) to
jump to any page, stack or container.

## What you need

- A Linux server with a 64-bit Intel or AMD (amd64) or ARM (arm64)
  processor.
- Docker Engine 25.0 or newer with the Compose plugin.
- A domain name, such as `docker.example.com`, and a reverse proxy that
  serves it over HTTPS. Docker Manager does not work over plain HTTP.

Docker Desktop, rootless Docker, the Docker built into NAS systems and
Docker Swarm are not supported.

<Callout type="warn" title="Protect your sign-in">
  The agent has full control of Docker, and so of the whole server. Anyone
  who can sign in with enough permissions can do the same. Use a strong
  password and two-factor sign-in (see
  [Users & Groups](/users-and-groups#your-account)).
</Callout>
