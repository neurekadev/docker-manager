---
title: Configuration
description: The settings you are most likely to change.
---

All settings live in the `.env` file next to `compose.yaml`. After a change,
run `docker compose up -d` again.

## Manager and web server

| Setting | Default | Change it when |
| --- | --- | --- |
| `DOCKER_MANAGER_HOST` | `localhost` | Always: your DNS name. |
| `DOCKER_MANAGER_TLS` (Caddy) | `internal` | You want a public certificate: put your email address. |
| `DOCKER_MANAGER_HTTP_PORT` / `DOCKER_MANAGER_HTTPS_PORT` | `80` / `443` | Those ports are taken on the host. |
| `DOCKER_MANAGER_MAX_BODY_SIZE` | `1GB` | You upload or restore larger files. |
| `DOCKER_MANAGER_TRUSTED_PROXIES` | Docker's default networks | Containers you do not trust share the `docker-manager` network, or your Docker uses other address pools. |
| `DOCKER_MANAGER_LOG_LEVEL` | `info` | You need more detail (`debug`) for a problem. |

## Agents

| Setting | Default | Change it when |
| --- | --- | --- |
| `DOCKER_AGENT_MANAGER_URL` | none | Agents on other hosts: always your `https://` address. |
| `DOCKER_AGENT_ENROLLMENT_TOKEN` | empty | Connecting a new agent (remove it afterwards). |
| `DOCKER_AGENT_ENVIRONMENT_NAME` | host name | You want another display name for the host. |
| `DOCKER_AGENT_MANAGER_CA_FILE` | empty | Your certificate comes from a private certificate authority. |
| `DOCKER_AGENT_STACK_ROOTS` | empty | You keep stacks in a host folder such as `/opt/stacks` and want Docker Manager to manage them where they are. Also mount the folder at the same path (`/opt/stacks:/opt/stacks`). |
| `DOCKER_AGENT_LOG_LEVEL` | `info` | You need more detail (`debug`) for a problem. |

## Backups to a local folder

Docker Manager only writes backups to folders you allow. Mount the folder
into the container at the same path and list it in the `.env` file:

| Setting | Default | Change it when |
| --- | --- | --- |
| `DOCKER_MANAGER_BACKUP_LOCAL_ROOTS` | empty | A backup repository on the manager's host should live in a local folder, for example `/srv/backups` (mount `/srv/backups:/srv/backups`). |
| `DOCKER_AGENT_BACKUP_LOCAL_ROOTS` | empty | The same for another host: set it on that host's agent. |

Separate several folders with commas. Without them, use an S3 bucket.

## Mounts you must keep

The agent needs the Docker socket and Docker's volume folder mounted at the
**same path** inside the container
(`/var/lib/docker/volumes:/var/lib/docker/volumes`). Keep these lines of
the example unchanged. If your Docker keeps its data somewhere else (see
`docker info -f '{{.DockerRootDir}}'`), replace `/var/lib/docker` on both
sides.

To import existing projects, add a read-only mount below `/import`; see
[Usage](./usage#import-projects-you-already-run).

## Your data

Everything Docker Manager stores is in Docker volumes. `docker-manager_data`
holds the database **and its key file**: back it up (Docker Manager's own
backups do this once set up) and never delete it.
