# Verification matrix (#12 → #29)

Every verification item of the v1 release issue #12 mapped to the
automated tests that check it, or to a documented manual procedure with
the reason it is manual. Suites and how to run them:
[harness.md](harness.md). `test/verification` (`TestVerificationMatrix`)
parses this file on every `go test ./...`: every row must have evidence,
every named Go test, Playwright/Vitest file and title, smoke step, devstack
group, workflow job and repository path must exist, and a row naming a
test that cannot run on the Windows development host without Docker must
say so in its status.

## How to read it

**Evidence** names tests the way the checker resolves them:

- `TestXxx` / `FuzzXxx`: a Go test function (`go test -run`).
- `name.spec.ts` / `name.test.ts` (optionally followed by quoted test
  titles): a Playwright spec in `e2e/tests/` or a Vitest file in
  `web/src/` (paths are given where a base name is ambiguous).
- `smoke:<step>`: a step of `scripts/smoke/deploy-smoke.sh` (extended
  `smoke` job, against the published `:edge` images on `main`).
- `devstack:<group>`: a group of `scripts/ci/e2e-devstack.sh` (Playwright
  against the Docker-free devstack; extended `e2e-devstack` job).
- `job:<name>`: a whole workflow job is the check (a script, not a test
  function).

**Where**: `PR` = the `ci.yaml` PR suite (`go`, `web`, `policy`, `vuln`,
`licenses`, `static-build`, `images`); `X:job` = that job of
`extended.yaml`.

**Status** (one or more, joined with `+`):

- `automated — ran locally`: executed and green on the Windows
  development host on 2026-09-25 (`bash scripts/check.sh`, the devstack
  Playwright runner, the Docker-free tagged tests listed below).
- `automated — written, not yet executed (CI unavailable)`: needs Docker,
  Linux or the published images. GitHub Actions has been unavailable since
  2026-09-25 (account out of minutes), so these have not run against the
  current `main`; several ran green in earlier CI runs (cited). They are
  listed as pending in #12's closing comment.
- `manual`: a documented procedure with the reason it is not automated.

Release gate: every automated row green in CI, every manual row executed
and recorded on #12.
